# Pomodoro timer and overlay maker

## What this is
A browser-only web app with two jobs:
1. A live Pomodoro timer (focus / break / rounds, lead-in, end screen, bell, full screen).
2. A renderer that turns the same timer into a video file to lay over footage:
   - Green or blue screen MP4 (H.264, AAC or Opus bell audio)
   - Transparent WebM (VP9 with alpha, Opus bell audio)

Everything runs on the user's machine. There is no backend, no upload, no account.

## Starting point
`reference/pomodoro-overlay.html` is the working prototype. Treat its behaviour and
visuals as the spec. Do not change how the timer looks or counts unless asked.
Never edit that file — it is the reference the goldens were captured from.

## Stack
- Next.js (App Router) + TypeScript, deployed on Vercel
- `mediabunny` from npm for encoding and muxing (replaces the CDN import in the prototype)
- The four fonts are pinned into `public/fonts/` by `npm run fonts`, never loaded
  from a CDN, so the renderer can never draw with a fallback face
- No database, no auth, no API routes. If that changes, it is a deliberate decision,
  not a drive-by addition.

### Why Next.js and not Vite
This is the first of several small products, and the SEO pages and writing that
drive traffic to them live on the same domain as the product. That is a folder in
Next and a second toolchain in Vite. The reusable parts of this repo become the
starter for the next product.

## The one Next.js trap
WebCodecs does not exist during server rendering. The tool must be loaded as a
client-only dynamic import:

```ts
const Tool = dynamic(() => import("@/src/ui/Tool"), { ssr: false });
```

Anything touching `VideoEncoder`, `AudioContext`, `canvas`, or `localStorage` sits
behind that boundary.

## Structure
React wraps the controls. The render core stays plain TypeScript with no React and
no DOM in it, so it can be tested directly and moved into a worker later.
Nothing under `src/` outside `src/ui/` may import React.

```
app/
  layout.tsx            metadata, OG image, analytics, fonts.css
  page.tsx              landing copy + the tool
src/
  timeline.ts           build segments, stateAt(t), formatting
  draw.ts               drawFrame(ctx, W, H, timeline, t, settings, mode) — pure
  bell.ts               bell synthesis shared by live playback and export
  live.ts               live timer loop, bells, title, wake lock
  export.ts             render pipeline — takes a canvas and a progress callback,
                        touches no DOM, so it can move into a Web Worker later
  ui/Tool.tsx           client-only shell, controls, settings persistence, preview
public/fonts/           pinned woff2 + fonts.css, generated by npm run fonts
reference/              the prototype. Read-only.
scripts/                font pinning, harness generation, golden capture
tests/golden/           committed reference PNGs + timeline.json
tests/                  Playwright tests
```

## Rules
- `drawFrame` must stay pure and resolution-independent. The preview and the export
  both call it, so what the user sees is what they get.
- `export.ts` must not touch the DOM. It gets a canvas and a callback. This is what
  makes the Web Worker move a small change rather than a rewrite.
- The prototype's `window.claude.use("downloads")` path is claude.ai-only. In this app,
  save files with the File System Access API where available, else a normal download link.
- Never claim MP4 supports transparency. Transparent output is WebM only.
- Colour warnings for green/blue screen and the no-shadow rule on keyed backgrounds stay.
- Keep it accessible: keyboard focus visible, labels on every control, reduced motion respected.

## Tests that must pass before any deploy

### Golden frames — the ones that catch a wrong picture
`tests/golden/` holds 17 PNGs captured from the prototype at 1280x720, covering every
segment kind, all four fonts, all three styles, both screen colours, transparent,
plates, position, scale, count-up, and labels off.

`drawFrame` must reproduce each within a small perceptual tolerance. This is the test
that matters: ffprobe can confirm a video has the right codec, size and duration while
every frame is blank. Only a pixel comparison catches that.

`tests/golden/timeline.json` pins the timeline maths — 248s total, 6 segments, and the
clock reading at five sample times. A change to `buildTimeline` or `fmtClock` fails here
rather than silently shifting every frame.

Re-capturing goldens needs `npm run golden -- --force` and a reason in the commit
message. It rewrites the contract, so it is never a casual fix for a failing test.

### Video output
Base session throughout: 1 min focus, 1 min break, 2 rounds, 3 s lead-in, 5 s end.
That is 3 + (60+60)x2 + 5 = **248 s**, confirmed against the prototype.

- Render at 720p / 10 fps in green, then check with ffprobe: h264, 1280x720, 248 s.
- Same session as transparent WebM: vp9 with alpha_mode=1, and a corner pixel with alpha 0.
- Extract a frame from the rendered video and compare it to the matching golden, so the
  export path and the preview path are proven to agree.
- Frame at t=5 s reads 00:58 with the Focus label.

ffmpeg and ffprobe come from npm (`ffmpeg-static`, `@ffprobe-installer/ffprobe`), not
Homebrew, so CI behaves the same as a laptop.

## MVP scope
In: the port, capability detection on load, a render size guard, Screen Wake Lock,
metadata and OG image, analytics, an inline email capture, licence notices.

Out, deliberately: Web Worker rendering, StreamTarget for long renders, PWA, watermark
and payment, programmatic SEO pages. Each is cheap to add later and none of them block
a first ship.
